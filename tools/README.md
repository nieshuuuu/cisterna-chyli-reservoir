# tools/ — things that get deployed, not imported

Nothing here is part of the `cc_reservoir` package. These are the operator-facing files that
live on the lab share, kept under version control so they stop being orphans nobody can diff.

## `painter_bundle/`

The files at the root of the painter bundle on the share:

```
Z:\ImageData\Lymph_Studies\Cisterna_Chyli_and_Thoracic_Duct_Segmentation\2_CT_volumes_and_painter\
```

| file | what it does |
|---|---|
| `Paint.bat` / `Paint.ps1` | **the launcher.** Syncs, opens the painter on a local copy, syncs back |
| `Sync_My_Work.ps1` | the sync itself; `Paint.ps1` calls it before and after the session |
| `Sync_My_Work.bat` | double-clickable wrapper, for syncing without painting |
| `Start_CC_Painter.bat` | kept for muscle memory; now just calls `Paint.bat` |
| `start_cc_painter.sh` | Mac/Linux. Opens the painter but cannot sync — says so, prints the `rsync` |
| `README.md` | the bundle's own documentation |

`sync-cc.ps1` copies these to the bundle root every run, so editing them here and committing is
all it takes to reach everyone. **The copy is by explicit filename and never uses `/MIR`** — the
bundle root also holds `data_fullres` (16 GB of CT and masks) and `software\`, and a mirror there
would delete them.

## `share_docs/`

The README files that live on the share itself, one folder per destination:

| here | deploys to |
|---|---|
| `share_docs/root/` | the segmentation root (`Cisterna_Chyli_and_Thoracic_Duct_Segmentation\`) |
| `share_docs/1_masks_USE_THESE/` | `1_masks_USE_THESE\` |
| `share_docs/3_old_masks_superseded/` | `3_old_masks_superseded\` |

`root` is the one special name; every other folder maps to a folder of the same name under the
segmentation root. Adding a destination means adding a folder here, nothing else.

These are what a new person reads first, and they were drifting on the share with no history —
the same orphan problem as the launchers. Same copy rule: **explicit filenames, never `/MIR`**,
since two of those destinations hold the delivered masks. A destination folder that does not
exist is logged and skipped rather than created, so a renamed folder surfaces as a note instead
of a README quietly appearing in the wrong place.

Not included, deliberately: `quarantine_frames.txt` and `sidecar_manifest.csv` in
`1_masks_USE_THESE\`. Those are regenerated by `audit_edit_sidecars.py` whenever the merge is
re-run — outputs, not documents.

## `sync-cc.ps1`

Versioned copy of the scheduled task's script. The task runs
`C:\Storage\CisternaChyli\cc_autosync\sync-cc.ps1`, not this file — a script that overwrites
itself mid-run is a bad idea, and the deployed copy is machine-specific anyway (it holds the
local clone path). The running copy reports drift against this one in `sync.log` rather than
updating itself.

**So: after editing `tools/sync-cc.ps1`, copy it to `cc_autosync\` by hand.** The log will nag
until you do.

## What flows where

```
  repo  src/cc_reservoir/      --(sync-cc.ps1, robocopy /MIR)-->  bundle software\src\cc_reservoir\
  repo  tools/share_docs/*/    --(sync-cc.ps1, named files)  -->  the matching share folders
  repo  tools/painter_bundle/  --(sync-cc.ps1, named files)  -->  bundle root
  local painted masks          --(Sync_My_Work.ps1, newer-only)-->  bundle data_fullres\
  bundle data_fullres\         --(merge_mask_archives.py, manual)-->  1_masks_USE_THESE\
```

Only the last step is deliberate rather than automatic: it is where someone decides which
version of a mask wins.
